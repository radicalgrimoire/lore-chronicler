# Chroniclerの変更一覧・Stage／Unstage実装方針

## 目的

選択中のプロジェクトで、現在ステージされているファイルの一覧を確認できるようにする。

現在の左側のツリーはローカルファイルの一覧であり、Loreの変更状態は表示していない。

## 操作の流れ

1. 外部のエディターなどでローカルファイルを編集する。
2. 変更を検出し、追加・編集・削除などを作業画面右側の「変更」一覧に表示する。
3. 利用者がファイルを選び、Stageで次のcommit対象にする。
4. 必要に応じてUnstageで対象から外す。ローカルの編集内容は破棄しない。
5. 将来の段階でcommitとpushを実装し、Submitの操作体験を検討する。

Stageは編集後のcommit準備であり、サーバーへの送信は行わない。commit・push・Submitは今回のStage／Unstageの実装範囲に含めない。

## 実装の順序

1. 採用中のLore SDKと対応するLore本体・CLIの仕様を確認し、試用リポジトリでstatusとscanの挙動を検証する。
2. 検出した変更とステージ済みの変更を区別して表示する。選択したプロジェクトのローカル状態であることを明示する。
3. 選択したファイルのStageとUnstageを追加し、操作後に状態を再取得する。対象や失敗を利用者に分かるように表示する。
4. 複数選択、追加・編集・削除、ステージ後にさらに編集されたファイルなどを検証する。
5. 大量ファイルでのscan時間、UIの応答性、一覧の仮想化とメモリ使用量を確認する。

外部で編集された変更の検出にはLoreのscanが必要になる。scanは単なる画面の再描画ではなく、ローカルの管理情報も更新する。現在の「リフレッシュ」はローカルファイルツリーの再読み込みなので、変更状態のscanとは区別する。

## 検証・安全性

- [ ] 採用中のSDKバージョンでstatus、scan、Stage、UnstageのAPI・イベント・失敗時の挙動を確認する。
- [ ] 試用リポジトリで追加・編集・削除、複数選択、ステージ後の再編集、Unstage後の編集内容保持を確認する。
- [ ] 変更なし、アクセス権不足、ファイル使用中、途中失敗、プロジェクト切り替え時の挙動を確認する。
- [ ] 大量ファイルでUIをブロックせず、scan中と終了後の状態・エラーが利用者に分かることを確認する。
- [ ] ローカル変更を意図せず破棄せず、Stageだけでサーバーに送信しないことを確認する。
- [ ] 自動テストに加え、実環境の試用リポジトリで操作を確認する。
